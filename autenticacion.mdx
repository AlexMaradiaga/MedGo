La API de Medgo\+ utiliza autenticación basada en **tokens Bearer** gestionados por [Laravel Sanctum](https://laravel.com/docs/sanctum). Cada vez que un usuario inicia sesión, el sistema genera un token personal de acceso que debe incluirse en el encabezado `Authorization` de todas las solicitudes que requieran autenticación. Los tokens no tienen una fecha de expiración fija, pero pueden ser revocados explícitamente al cerrar sesión.

## Obtener tu token

Para obtener un token de acceso, envía tus credenciales al endpoint de inicio de sesión. Este endpoint es público y no requiere autenticación previa.

```bash
curl -X POST https://api.medcoreglobal.com/api/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "maria@ejemplo.com",
    "password": "TuContraseña123"
  }'
```

**Respuesta exitosa (`200 OK`):**

```json
{
  "success": true,
  "status": "success",
  "data": {
    "id": 42,
    "email": "maria@ejemplo.com",
    "rol_id": 3,
    "entidad_id": 1,
    "tipo_entidad": "clinica"
  },
  "access_token": "1|abc123...",
  "token_type": "Bearer"
}
```

El valor del campo `access_token` es tu token de acceso personal. Úsalo en todas las solicitudes subsiguientes. El campo `rol_id` indica el rol asignado al usuario: `1` para Administrador, `2` para Médico y `3` para Paciente.

<Note>
  Las cuentas de **médicos** deben ser aprobadas por un administrador de clínica antes de poder iniciar sesión. Si recibes un error `403` al intentar autenticarte con una cuenta médica recién creada, contacta al administrador de tu clínica para que active tu perfil.
</Note>

## Enviar el token en cada solicitud

Una vez obtenido el token, inclúyelo en el encabezado HTTP `Authorization` con el esquema `Bearer` en cada solicitud a endpoints protegidos.

**Ejemplo con curl:**

```bash
curl -X GET https://api.medcoreglobal.com/api/doctores \
  -H "Authorization: Bearer 1|abc123..." \
  -H "Accept: application/json"
```

**Ejemplo con JavaScript (Fetch API):**

```javascript
const response = await fetch('https://api.medcoreglobal.com/api/doctores', {
  method: 'GET',
  headers: {
    'Authorization': 'Bearer 1|abc123...',
    'Accept': 'application/json',
    'Content-Type': 'application/json'
  }
});

const doctores = await response.json();
console.log(doctores);
```

**Ejemplo con JavaScript (Axios):**

```javascript
import axios from 'axios';

const client = axios.create({
  baseURL: 'https://api.medcoreglobal.com/api',
  headers: {
    'Authorization': 'Bearer 1|abc123...',
    'Accept': 'application/json'
  }
});

const { data } = await client.get('/doctores');
console.log(data);
```

<Warning>
  Mantén tu token en un lugar seguro. **Nunca lo expongas en repositorios públicos, logs de aplicación o en el código fuente del frontend.** Almacénalo en variables de entorno, un gestor de secretos o, para aplicaciones web, en una cookie `HttpOnly`. Cualquier persona con acceso a tu token puede realizar solicitudes en tu nombre con todos tus permisos.
</Warning>

## Cerrar sesión

Para invalidar tu token activo y cerrar la sesión de forma segura, realiza una solicitud `POST` al endpoint de logout. Tras este llamado, el token queda revocado y no puede ser utilizado nuevamente.

```bash
curl -X POST https://api.medcoreglobal.com/api/logout \
  -H "Authorization: Bearer 1|abc123..." \
  -H "Accept: application/json"
```

**Respuesta exitosa (`200 OK`):**

```json
{
  "status": "success",
  "message": "Sesión cerrada exitosamente y token eliminado."
}
```

## Cambiar contraseña

Los usuarios autenticados pueden actualizar su contraseña enviando la contraseña actual junto con la nueva contraseña y su confirmación. Este endpoint requiere que el usuario esté autenticado.

```bash
curl -X PUT https://api.medcoreglobal.com/api/auth/password \
  -H "Authorization: Bearer 1|abc123..." \
  -H "Content-Type: application/json" \
  -d '{
    "usuario_id": 42,
    "old_password": "TuContraseña123",
    "new_password": "NuevaContraseña456",
    "new_password_confirmation": "NuevaContraseña456"
  }'
```

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `usuario_id` | integer | ID del usuario autenticado (campo `data.id` devuelto al iniciar sesión) |
| `old_password` | string | Contraseña actualmente en uso |
| `new_password` | string | Nueva contraseña deseada (mínimo 8 caracteres) |
| `new_password_confirmation` | string | Debe coincidir exactamente con `new_password` |

**Respuesta exitosa (`200 OK`):**

```json
{
  "status": "success",
  "message": "Contraseña actualizada con éxito."
}
```

Si la contraseña actual no coincide o la confirmación de la nueva contraseña es incorrecta, recibirás un error `422` con los detalles de validación.

## Errores de autenticación

La API devuelve códigos de estado HTTP estándar para indicar el tipo de error de acceso. Consulta la tabla a continuación para manejar correctamente cada caso en tu integración:

| Código HTTP | Nombre | Causa probable | Acción recomendada |
| --- | --- | --- | --- |
| `401 Unauthorized` | Token inválido o ausente | El encabezado `Authorization` no fue enviado, el token está mal formado o ya fue revocado (logout previo). | Solicitar al usuario que inicie sesión nuevamente para obtener un token válido. |
| `403 Forbidden` | Rol incorrecto o cuenta inactiva | El usuario no tiene el rol necesario para acceder al recurso solicitado, o su cuenta ha sido desactivada por un administrador. | Verificar que el usuario tenga los permisos correspondientes. Si la cuenta fue desactivada, contactar al administrador de la clínica. |
| `422 Unprocessable Entity` | Validación fallida | Los datos enviados en el cuerpo de la solicitud no cumplen las reglas de validación (campos requeridos ausentes, formato incorrecto, contraseña que no coincide, etc.). | Revisar el campo `errors` en el cuerpo de la respuesta para identificar y corregir cada campo con error. |
